# triangle-tilings

Draws the tiling generated by the triangle group **Δ(p,q,r)**, the group
generated by reflections `a`, `b`, `c` in the sides of a triangle with angles
π/p, π/q, π/r. The geometry is chosen automatically:

| 1/p + 1/q + 1/r | Geometry | Model |
|---|---|---|
| < 1 | hyperbolic | Poincaré disk |
| = 1 | Euclidean | plane |
| > 1 | spherical | stereographic projection (unit circle = equator) |

An order of `0` means ∞. That vertex is ideal: it lies on the boundary circle
with angle 0, the two reflections meeting there compose to a parabolic map
(the pair has no relation), and the group is always hyperbolic. Infinitely
many tiles meet at each cusp, so `--depth` and `--min-size` decide how far
into the cusp the picture goes.

Each tile is labelled by a reduced word in `a`, `b`, `c`. Alongside the image,
the tool writes a JSON file of `{word: vertex coordinates}` that you can check
against other code (for example, automata for the word problem).

| Δ(2,3,7) | Δ(3,3,4) | Δ(2,4,4) | Δ(2,3,5) |
|---|---|---|---|
| ![](examples/tiling_2_3_7_deep.png) | ![](examples/tiling_3_3_4.png) | ![](examples/tiling_2_4_4.png) | ![](examples/tiling_2_3_5_full.png) |

## How it works

1. **Fundamental triangle**: `V_p` sits at the origin, `V_q` on the positive
   real axis, and `V_r` on the ray at angle π/p. The distances |V_pV_q| and
   |V_pV_r| come from the dual law of cosines (with cosh in H², cos in S²) and
   are then mapped to the model (`tanh(d/2)` in the disk, `tan(d/2)`
   stereographically). Two sides are straight lines through the origin. The
   third side is a circle orthogonal to the unit circle (hyperbolic), a great
   circle (spherical), or a line (Euclidean).
2. **Reflections**: these are anti-Möbius maps `z ↦ M·conj(z)`. Group elements
   are stored as `(M, conj)` pairs, and M is renormalised to determinant 1
   after each step so long words don't overflow.
3. **BFS**: words are extended on the right, never repeating a letter
   (s² = 1). A tile is kept the first time its rounded centroid is seen.
   Spherical tiles are deduplicated by their centroid on the sphere, because
   plane coordinates blow up near ∞. Tiles smaller than `--min-size` are
   dropped and not expanded.
4. **Rendering**: each edge is drawn as a true circular arc through the images
   of its two endpoints and an interior point, so geodesics in the disk are arcs
   orthogonal to the boundary, not chords.

## Usage

```bash
python tiling.py --pqr 2 3 7                  # → data/2_3_7/d12_m0.001.png + .json
python tiling.py --pqr 2 3 7 --svg            # … + .svg
python tiling.py --pqr 2 3 7 --html           # … + .html (zoomable viewer)
python tiling.py --pqr 2 3 7 --svg --html     # all four files
```

| Option | Default | Meaning |
|---|---|---|
| `--pqr P Q R` | required | triangle angles π/P, π/Q, π/R; `0` (or `inf`) means ∞ |
| `--depth N` | `12` | max word length |
| `--color {alternate,wordlength,none}` | `alternate` | `alternate` uses word-length parity (the standard checkerboard); `wordlength` uses a viridis gradient; `none` draws white tiles with outlines only |
| `--labels` | off | print each tile's group word (`e` = identity) |
| `--svg` | off | also write an SVG |
| `--html` | off | also write the zoomable HTML viewer |
| `--out PATH` | `data/<group>/<settings>` | override the base name for every output; a `.png`/`.svg`/`.html` suffix is dropped, and `.svg`/`.html` also switch that format on |
| `--json PATH` | base name + `.json` | word → vertices export |
| `--min-size X` | `1e-3` | skip tiles with Euclidean diameter below X |

```bash
# Dense {7,3} picture: hyperbolic words get long fast, so raise the depth
python tiling.py --pqr 2 3 7 --depth 40 --out 237.png

# All 120 elements of the icosahedral group (longest word has length 15)
python tiling.py --pqr 2 3 5 --depth 15

# 0 = ∞: ideal vertices on the boundary circle (cusps)
python tiling.py --pqr 2 3 0 --depth 30           # Δ(2,3,∞), the extended modular group
python tiling.py --pqr 0 0 0 --depth 30           # ideal triangle group

# Labelled tiles
python tiling.py --pqr 3 3 4 --depth 6 --labels --out labels.png
```

### Output layout

Everything goes into the project's `data/` folder (git-ignored), one folder
per group, with file names built from the settings so different runs never
overwrite each other:

```
data/
├── 2_3_7/
│   ├── d12_m0.001.png                 # depth 12, min-size 0.001
│   ├── d12_m0.001.json
│   ├── d50_m0.0001.html               # --html run (+ .png, .json)
│   └── d12_m0.001_wordlength_labels.png
└── 2_3_inf/                           # ∞ is written "inf"
    └── d30_m0.0005.png
```

The color is added to the name only when it isn't `alternate`, and `_labels`
only with `--labels`. Rerunning with identical settings overwrites that run.

A PNG is always written. `--svg` and `--html` only add files, and every
output in a run is drawn from the same tiles (same depth, `--min-size`,
coloring and labels).

### Zoomable viewer (`--html`)

A single self-contained `.html` file; open it in any browser. It draws on a
canvas and on every redraw skips tiles that are off-screen or smaller than
about a pixel, so it stays responsive with hundreds of thousands of tiles.
Zooming in reveals the small tiles near the boundary.

- Scroll or pinch to zoom, drag to pan; `+` / `−` / `0` (reset) / `L` (labels)
- Hover a tile to see its word, length and vertices; click to copy the word
- Labels appear once a tile is big enough to fit its word

The viewer can only show tiles that were generated, so for deep zooming raise
`--depth` and lower `--min-size`. The grey zone near the boundary is where the
data runs out:

```bash
python tiling.py --pqr 2 3 7 --depth 50 --min-size 1e-4 --html   # ~155k tiles, ~12 MB
```

Each 10× smaller `--min-size` gives roughly 15–20× more tiles, so going much
past `1e-4` makes large files.

### JSON format

```json
{
  "e": [[0.0, 0.0], [0.1406, 0.0], [0.0, 0.2661]],
  "a": [[0.2109, 0.1170], [0.1406, 0.0], [0.0, 0.2661]],
  ...
}
```

- Vertices are always listed in the order (V_p, V_q, V_r), the images of the
  fundamental triangle's vertices with angles π/p, π/q, π/r.
- The word `"abc"` means g = a∘b∘c, and the tile is g(T). Words are the first
  ones BFS finds, so they have minimal length but are not a chosen normal form
  (such as shortlex). Normalise both sides before comparing them to an
  automaton's output.
- In the spherical case, a vertex at ∞ is written as `null`.
- Reflection sides: `c` is the real axis (V_p to V_q), `b` is the line at angle
  π/p (V_p to V_r), and `a` is the side from V_q to V_r. This gives
  (ab)^r = (bc)^p = (ca)^q = 1.

### Tests

```bash
python -m unittest -v      # or: python -m pytest -q
```

The tests check that:

- reflections are involutions and fix their own sides;
- (ab)^r = (bc)^p = (ca)^q = 1, with exact orders and no smaller power giving
  the identity;
- with an order of 0 (∞), that pair composes to a parabolic map (trace² = 4)
  of infinite order, and the ideal vertex lies on the unit circle;
- the triangle's angles, measured from the arc tangents, equal π/p, π/q, π/r;
- side `a` is orthogonal to the unit circle in the hyperbolic case and is a
  great circle in the spherical case;
- Δ(2,3,5) has exactly 120 tiles;
- recomposing each word from scratch reproduces its tile;
- a tile and its BFS parent share an edge;
- the HTML viewer's packed data decodes back to the same words, vertices and
  arcs.
